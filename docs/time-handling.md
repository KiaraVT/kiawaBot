# Time and Attendance Handling Architecture

## 1. Overview

This document describes how date, time, duration, and stream attendance calculations are governed across the repository.

All temporal logic is centralized in [timeUtils.js](../timeUtils.js) using Luxon (pinned at `3.7.2`).

## 2. Historical Defects and Root Causes

Prior implementations suffered from several architectural defects:

1. Ambiguous 12-hour formatting: Quote timestamps relied on manual modulo math and AM/PM strings. At noon (12:00 PM), arithmetic errors could format timestamps as 12:00 AM, corrupting display and sorting order.
2. Clock skew and unvalidated intervals: Date subtractions (`currentStart - currentStreamStart`) did not guard against negative differences caused by clock skew or out-of-order events.
3. Hardcoded Pacific reset times: Daily attendance boundaries relied on static hour offsets without accounting for daylight saving transitions or streamer travel across timezones.
4. Duplicated streak progression logic: Attendance progression had two separate 40-line blocks differing only in whether a previous stream end time was recorded, leading to maintenance divergence.
5. Unmanaged global tracking: Active attendance tracking used a global object without lifecycle boundaries, risking unbounded memory growth across stream restarts.
6. Division by zero and modulo risks: Rotating interval indices and duration math lacked defensive boundary checks.

## 3. Core Principles

All code across the repository must adhere to the following principles:

### 3.1 UTC Storage and Exchange
- All timestamps written to JSON storage or emitted over API and WebSocket endpoints must use standard ISO-8601 UTC strings generated by `getUtcNowIsoString()`.
- Example: `2026-10-10T12:00:00.000Z`.

### 3.2 Quote Timestamp Formatting
- Quote records and chat confirmations format timestamps using 24-hour UTC format with seconds: `yyyy-MM-dd HH:mm:ss`.
- Example: `2026-10-10 12:30:45`.
- This eliminates ambiguity around noon and midnight.

### 3.3 Stream Attendance Sessions
- Day cutoff boundary: Daily attendance resets are anchored to 06:00:00 local time in the active streamer timezone (default `America/Los_Angeles`).
- Late-night broadcasts: Broadcasts starting between midnight and 06:00 local time belong to the previous calendar day's broadcast session.
- Session detection: A stream is evaluated as a new attendance session if more than 5 hours have elapsed since the prior stream ended (`isNewStreamAttendanceSession`), or if stream start times cross the 06:00 local daily cutoff.
- Restarts within 5 hours: Restarts within 5 hours are treated as continuations of the active session and do not reset attendance counters.

### 3.4 Dynamic Streamer Timezone
- The broadcaster may view or change the active timezone at runtime using broadcaster-only chat commands:
  - `!timezone`: Displays the current streamer UTC offset and ISO timestamp without disclosing geographic region (e.g. `UTC-7`). Broadcaster-only (`isbroadcaster === true`).
  - `!settimezone <zone>`: Updates the streamer timezone immediately and reports the new UTC offset and ISO timestamp. Broadcaster-only (`isbroadcaster === true`).
- Privacy and location masking: Neither command discloses geographic city or country names; responses provide numeric UTC offsets and ISO timestamps.
- Accepted inputs for `!settimezone`:
  - IANA timezone identifiers (e.g. `America/Chicago`, `Asia/Tokyo`, `Europe/London`).
  - Full UTC offsets (e.g. `UTC+2`, `UTC-5`, `+05:00`, `-08:00`).
  - Bare offsets (e.g. `+5`, `-8`, `+5:30`).
  - GMT aliases (e.g. `GMT+2`, `GMT-5`).
- Updated timezones are normalized via `normalizeTimezone()`, applied in memory, and persisted to `Timezone` in `data/streaks.json`.
- Broadcaster permission: Only users with broadcaster status (`isbroadcaster === true`) can invoke `!timezone` or `!settimezone`.
- Silent failure for unauthorized users: Non-broadcaster chatters invoking `!timezone` or `!settimezone` fail silently with no chat response emitted.

### 3.5 Session-Bound Attendance Tracking
- The `StreamAttendanceSessionTracker` class replaces unmanaged global dictionaries.
- It caches user IDs who have already checked in during the active stream session.
- It automatically clears when a new stream start timestamp is detected, and can be manually cleared upon stream offline/online events.

### 3.6 Defensive Mathematics
- Safe interval check (`isWithinRestartWindow`): Verifies `0 <= (laterTime - earlierTime) < maxDurationMs`. Rejects negative intervals and out-of-order events.
- Safe division (`safeDivideDuration`): Protects against zero, negative, or NaN divisors.
- Safe index rotation (`safeRotateIndex`): Protects against modulo by zero on empty arrays.
- Corrupt date recovery: If user streak records contain invalid or unparseable timestamps, `calculateUserStreakProgression` recovers gracefully by starting a fresh streak count of 1 while preserving the user's recorded `Best_Streak`.

## 4. Module Reference

The centralized functions are located in [timeUtils.js](../timeUtils.js):

- `parseIsoDateTime(isoString)`: Parses ISO strings into UTC Luxon DateTime instances.
- `getUtcNowIsoString(dateTime)`: Generates ISO-8601 UTC strings.
- `formatQuoteTimestamp(dateTime)`: Formats timestamps for quotes as `yyyy-MM-dd HH:mm:ss`.
- `isWithinRestartWindow(earlier, later, maxMs)`: Validates positive durations within windows.
- `safeDivideDuration(numerator, divisor, fallback)`: Divisor-safe duration calculation.
- `safeRotateIndex(currentIndex, length)`: Zero-safe modular index increment.
- `normalizeTimezone(timezone)`: Canonicalizes IANA zones, bare offsets, and GMT aliases.
- `isValidTimezone(timezone)`: Validates timezone support.
- `getStreamerTimezone()`: Returns active streamer timezone.
- `getStreamerUtcOffset(refTime, zone)`: Returns formatted UTC offset (e.g. "UTC-7") masking geographic location.
- `getStreamerIsoString(refTime, zone)`: Returns ISO-8601 formatted date/time string with timezone offset.
- `setStreamerTimezone(newZone)`: Dynamically sets active streamer timezone.
- `resetStreamerTimezone()`: Resets timezone to default (`America/Los_Angeles`).
- `getDailyResetCutoffTime(refTime, zone)`: Computes 06:00 local cutoff time converted to UTC.
- `isNewStreamAttendanceSession(...)`: Evaluates stream gaps and broadcast day boundaries.
- `calculateUserStreakProgression(...)`: Pure function evaluating user streak updates.
- `findOldestTimestampKey(map)`: Finds key with oldest `createdAt` for FIFO eviction.
- `delayMilliseconds(ms)`: Promise-based asynchronous delay.
- `StreamAttendanceSessionTracker`: Session-bound tracker for attendance check-ins.
